How it gets everything out.

The portal is UAEU's Blackboard, on my own student account. Nothing below needs my password: I sign in once by hand, inside TinyFish, and the tool works from that saved sign-in.

  1. I sign in once, by hand

    TinyFish opens a browser, I sign in to Blackboard in it myself, and TinyFish keeps that session as a Browser Context Profile. No password is in the code, in the settings or in any Agent goal.

  2. The portal says what it holds

    Through that same signed-in TinyFish browser, Takehome reads the data Blackboard's own pages load for themselves: every course and term, the content of each course, the graded work, the announcements. It only ever asks to read.

  3. The TinyFish Agent reads each Grades page

    One Agent run per course, on the saved sign-in, returns every row exactly as the page shows it. A Grades page takes the Agent about three steps. A second kind of run reads the overview of all my courses, locked ones included.

  4. Every reading is checked

    The Agent's rows must be the portal's own rows, and each score must equal the portal's at the precision the page shows. A reading that fails is read once more, and if it fails again its rows stay marked "not read". Nothing is filled in.

  5. Only what changed is read again

    Content, announcements and documents come from the portal's own data on every run, which costs nothing. The Agent is sent only to courses whose graded work is not what the export already holds. Rows are merged by the portal's own ids, so none is taken twice.

  6. The documents come home whole

    The signed-in browser asks the portal where each document is; the portal answers with a link that works for a short time, and the bytes are saved with their SHA-256. Files over 25 MB are listed, not fetched.

  7. The documents become searchable

    TinyFish Fetch reads the same short-lived link and returns the text of each PDF and Word file. One command then looks inside all of them.

Where TinyFish is used

TinyFishWhat it does here
AgentReads the Grades overview and each course's Grades page on the saved sign-in, against a fixed answer shape
FetchTurns each PDF and Word file into text, so the export can be searched
Browser Context ProfileHolds the sign-in I made by hand. Its browser reads what the portal itself reports, for the check, and asks where each document is
RunsFollows every Agent run to its end and records its steps and its cost

So far: 69 Agent steps in the runs listed on the first page, $1.52 spent in all with the first tests, for 109 graded items in 12 open courses.

What it will not do

  • Change anything. Every Agent goal forbids Submit, Start, Begin, Send, Save, Delete and Mark.
  • Open a test I have not taken. Only the Grades page is read.
  • Take other students' work or names. A conversation is kept as a date and a size.
  • Go faster than a person. One or two pages at a time, never a burst.
  • Get past a sign-in page. If the saved sign-in has ended it stops and asks me to sign in again.
  • Pass its spending cap. Every run is booked in a ledger before the next one starts.

What comes home

takehome-data/
  export.json          everything, one file: courses, items, grades, files, announcements, messages, runs
  csv/                 one CSV per table, the same columns on every line
  files/<course>/      the documents themselves
  text/<course>/       PDFs and Word files as text
  changes/run-2.json   what each run added or changed
  manifest.json        counts and checks per course, every run, every dollar
  sealed.json          the only file that is ever published

Every row keeps the portal's own id. A grade row also says how it was checked: equal to the portal, different, not shown on the page, or not read yet.
